# AutoPrintCode

Агент для живых демонстраций кода. Он печатает заготовленный образец в любое окно (Блокнот, VS Code, веб-IDE, Jupyter) с позиции курсора, без ошибок и в заданном темпе, с мягким звуком клавиш.

## Запуск

Нужны Windows и Python 3.10+.

```
git clone https://github.com/Recyavik/AUTO_PRINT_CODE.git
cd AUTO_PRINT_CODE
pip install -r requirements.txt
python app.py        # или run.bat — без консоли
```

Без git можно скачать архив: на странице репозитория **Code → Download ZIP**.

При первом запуске создаётся папка `data/` с примером образца и звуками клавиш. Она не хранится в репозитории: у каждого своя база образцов и настроек.

## Как устроено

- **Образец** — занятие: лента **блоков** сверху вниз. Блок — это текст (Markdown с ролью: условие, пояснение, подсказка) или код.
- Образцы открываются во **вкладках**, чтобы быстро переключаться между ними: `Ctrl+Tab`, `Ctrl+1…9`, меню ☰.
- Вся база хранится в одном файле `data/templates.json`, рядом лежит резервная копия `.bak`. Настройки — в `data/settings.json`.
- **Импорт**: `.ipynb` (Jupyter), `.md`, `.json`. **Экспорт**: `.ipynb`, `.json`.
  Тетрадка импортируется как есть: каждая ячейка становится блоком, порядок сохраняется.

## Печать

1. Щёлкните по блоку кода, и он станет **активным** (зелёная рамка).
   Если выделить строки, напечатаются только они. Выделение сохраняется в образце.
2. Поставьте курсор в целевом окне.
3. `Ctrl+F9` запускает печать, повторное нажатие ставит на паузу, следующее продолжает.

| Хоткей | Действие |
|---|---|
| `Ctrl+F9` | старт / пауза / продолжить |
| `Ctrl+F10` | начать сначала |
| `Ctrl+F11` | стоп |
| `Ctrl+F12` / `Ctrl+Shift+F12` | следующий / предыдущий блок кода |

Все хоткеи можно сменить в **⚙ Настройки**. Они глобальные: срабатывают в любом окне и до самого окна не доходят.

## Защита во время печати

- **Сменилось активное окно** — печать встаёт на паузу.
- **Нажата клавиша или кнопка мыши** — печать встаёт на паузу, а случайная клавиша не попадает в код. Хоткеи приложения работают как обычно. Перехват ввода включается только на время печати; что именно было нажато, не записывается.
- **Окно запущено от администратора** — печать не начнётся, приложение покажет предупреждение. Windows молча отбрасывает ввод в такие окна, поэтому AutoPrintCode тоже нужно запустить от администратора.

## Профили окна

- **Блокнот / простое поле** — текст печатается как есть.
- **IDE (VS Code, веб-IDE, Jupyter)** — компенсирует «умный» редактор:
  - перед закрывающей скобкой или кавычкой и перед Enter стирается то, что редактор сам дописал справа (автоскобки, автокавычки), и закрываются подсказки автодополнения;
  - после Enter снимается автоотступ, а отступ печатается точно как в образце.

  Профиль рассчитан на печать в конец строки или в пустую строку: текст справа от курсора на текущей строке будет стёрт.

### Проверено в настоящих редакторах

| Редактор | Python | JavaScript |
|---|---|---|
| Блокнот Windows 11 (оба профиля) | ✓ | — |
| VS Code, настройки по умолчанию | ✓ | ✓ |
| Monaco (редактор Colab) | ✓ | ✓ |
| CodeMirror 6 (редактор JupyterLab 4) | ✓ | ✓ |

✓ — совпадение с образцом символ в символ при 1500 симв/мин. Образец включает автоотступы, вложенные скобки, тройные кавычки, f-строки, шаблонные строки и кириллицу.

Не проверено: JetBrains, HTML-файлы в VS Code (автозакрытие тегов — лучше отключить `html.autoClosingTags`).

### Надёжность ввода

**Мин. интервал нажатий** (Настройки → Печать, по умолчанию 30 мс). При 8–12 мс Блокнот Windows 11 терял и переставлял символы, при 30 мс набор точный. Если в каком-то редакторе пропадают символы — увеличьте интервал.

## Журнал

`data/logs/autoprint.log` (Файл → Открыть журнал работы). Пишутся служебные события: старт, пауза и её причина, целевое окно, ошибки. Набираемый текст и нажатия клавиш в журнал не попадают. Если что-то сработало не так на занятии — пришлите этот файл.

## Тесты

```
cd tests/pages && npm i && npm run build && cd ../..
python tests/run_editors.py notepad vscode browser
```

Тест сам открывает редакторы и печатает в них. Во время прогона не трогайте клавиатуру и мышь. Тестовые данные пишутся в `tests/_run`, рабочая `data/` не используется.
